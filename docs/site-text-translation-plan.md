# 后台控制的 AI i18n：加什么语言，前台就有什么语言（方案，待站长确认）

2026-11-05 站长的想法（第二版，取代同日第一版“只把站点文案接进翻译条目、语言只能选中英日”的方案）：

- 在后台“设置 → AI”里加一个“AI i18n”开关和一份“i18n 语言”列表，用语言代码填，和“摘要目标语言”“翻译目标语言”是同样的输入框。
- 这份列表就是前台语言菜单的来源：加了什么语言，前台就出现什么语言。
- 界面上的所有文字（按钮、菜单、提示、夜航岛播报）和站长写的站点文案，都只写中文，别的语言由 AI 翻。
- “AI”菜单下面加一个“i18n”子菜单，样子和“翻译”页一样，能看到每块文字翻成了哪些语言，也能逐条改。

本文只是方案，还没有改任何代码。

## 现在是怎么做的

| 文字 | 在哪 | 怎么翻 |
| --- | --- | --- |
| 界面文字：按钮、菜单、提示、播报，一共 382 条，其中 73 条要插入名字、数字 | `apps/web/lib/i18n/messages/zh.ts`、`en.ts`、`ja.ts` | 三种语言各手写一份 |
| 站点文案：首屏标题和说明、页脚那句话、版权说明、技术栈的标题和说明、站点描述、作品名和介绍 | 配置片段 `theme/yozora` 和它的 `i18n` | 英文、日文手写在片段里 |
| 文章、手记、页面的正文 | Core | AI 翻译，按“翻译目标语言” |
| 分类名、话题、心情、天气 | Core 的“翻译条目” | AI 翻译，按“翻译目标语言” |

前台支持哪些语言写死在 `apps/web/lib/i18n/config.ts`（中、英、日），语言菜单、网址前缀、sitemap 都按它来。

Core 的“翻译条目”已经有一套完整的机制：

- AI 生成，只翻新增的和中文改过的。
- 可以手改单条，结果缓存在 Redis。
- 前台带 `?lang=` 时，Core 把内容换成译文再返回。

本地库的 AI 设置：翻译开、自动生成开，翻译目标语言是 `["zh","en","ja"]`，服务商是 Deepseek（deepseek-flash）。

## 整体做法

1. 中文原文：界面文字仍然写在代码的 `zh.ts` 里，因为代码要按名字取用每一条。站点文案仍然写在片段 `theme/yozora` 里。
2. 交给 Core：
   - 界面文字的中文原文由前台推送给 Core。
   - 站点文案 Core 自己从片段、SEO 设置、作品里收集。
3. Core 用 AI 把它们翻成“i18n 语言”里的每种语言，存成翻译条目。站长可以在“AI → i18n”页里改。
4. 前台按当前语言向 Core 取整份界面文字，再把站点文案带 `?lang=` 读回来。缺译文的条目显示中文。
5. 语言菜单、网址前缀、sitemap 都跟着“i18n 语言”走。

## Core

1. **设置**：AI 设置里新增两项。
   - “启用 AI i18n”（`enableI18n`）。
   - “i18n 语言”（`i18nLanguages`，语言代码列表）。

   关掉开关时，前台只有中文。
2. **存储：复用“翻译条目”**（`translation_entries`）。生成、只翻改过的、手改、缓存这些都现成。新增四类：
   - 界面文字 `ui.text`：按条目名查（比如 `header.presence.label`）。
   - 站点文案 `site.text`：按中文原文查。
   - 作品名 `project.name`、作品介绍 `project.description`：按作品 id 查。

   “翻译词表”页不显示这四类，免得几百条界面文字把它淹没，它们都在新的“i18n”页里。
3. **界面文字的中文原文**：新增“上传原文”接口（要登录）。前台把 `zh.ts` 拍平成“条目名 → 中文”的一张表发过来，Core 存下最新一份：
   - 新增的条目，交给 AI 翻译。
   - 中文改了的条目，重新翻。
   - 代码里已经删掉的条目，跟着删掉。
4. **站点文案的收集**：Core 从片段 `theme/yozora` 读这些字段：`hero.title`、`hero.description` 的每一行、`footer.motto`、`copyright`、`techStack.title`、`techStack.description`。再加上 SEO 的“网站描述”，以及每个作品的名字和介绍。保存片段、SEO 设置或作品时，自动生成；中文改过的重新翻；用不到的旧条目删掉。
5. **生成**：
   - “AI i18n”开着时，以下情况自动生成：上传原文后、保存站点文案后、“i18n 语言”里新加了语言后（把这种语言整份翻一遍）。
   - “i18n”页也有手动的“生成翻译”按钮。
   - 界面文字有几百条，按分组分批交给 AI。
6. **AI 规则**：现有的短字段提示词是为一到五个词的分类名写的，界面文字和站点文案要单独一份规则：
   - 像网站界面那样简洁自然。
   - `{name}` 这类占位符原样保留，不翻译、不改名。
   - `**` 标记要挪到对应的词上。
   - 品牌和技术名词不翻（Yozora、GitHub、RSS）。

   保存前由 Core 自动检查：译文里的占位符和 `**` 必须和中文一模一样，对不上就不存，这一条前台继续显示中文，“i18n”页里标成“需要重翻”。
7. **给前台的公开接口**：
   - `GET /ai/i18n`：返回开关状态和语言列表。
   - `GET /ai/i18n/:lang`：返回这种语言整份界面文字的译文，只含已翻好的。
   - 片段 `theme/yozora`、作品列表、聚合接口里的站点描述，带 `?lang=` 时换成译文。只换上面那几个字段，别的片段原样返回。
8. **事件**：i18n 译文有变化时发 `I18N_UPDATE`（带上是哪种语言），Webhook 通知前台刷新缓存。“i18n 语言”有变化，走已有的 `OPTION_UPDATE`。
9. **文章正文的语言**：开着“AI i18n”时，文章、手记、页面的自动翻译也覆盖“i18n 语言”里的语言（和“翻译目标语言”取并集）。不然新加的韩语页面上，文章只能显示中文。

## 前台

1. **词典改成“中文原文 + 占位符”**：
   - 73 条带参数的条目，从函数改成一句带占位符的话，比如 `msg("已切换到{name}")`。`msg` 会把这句话包成一个函数，所以组件里照旧写 `t.locale.switched(name)`，几百处调用都不用改。
   - 有几条里面带判断，要拆成两条，由组件或小工具来选：“万字 / 字”改用浏览器的数字格式化；“显示 / 隐藏星星”；“正在用 / 正在听”那句；登录错误码那几条。
   - 前台中文渲染不变。
2. **取译文**：
   - 服务端的 `getT()` 按当前语言从 Core 取整份译文（`"use cache"`，标签 `i18n:<语言>`），缺的条目用中文补上，再交给客户端的 `useT()`。
   - 占位符在前台也再核对一遍，对不上就用中文。
   - `en.ts`、`ja.ts` 删掉。
3. **语言**：
   - 支持哪些语言不再写死，改读 Core 的 `GET /ai/i18n`，中文一直有。
   - 语言名用浏览器自带的 `Intl.DisplayNames` 显示各自的写法（English、日本語、한국어、Français）。
   - `<html lang>`、分享卡片的 `og:locale` 由语言代码直接算出来。
   - `proxy.ts`：每分钟最多读一次语言列表。按浏览器语言跳转时，只在开着的语言里挑。没开的语言（比如 `/ko/...` 关掉以后），跳回同一页的中文。
   - 语言菜单、手机菜单、文章页的语言分段、sitemap，都只列开着的语言。
4. **站点文案**：
   - 不再读片段里的 `i18n`。外文页面带 `?lang=` 读片段和作品，逐项和中文比较，没翻出来的显示中文并标 `lang="zh-CN"`。
   - 片段读不到时只保留中文占位，外文页面也显示中文占位。
5. **中文原文推送给 Core**：
   - 新增 `scripts/push-i18n-source.mjs`，把 `zh.ts` 拍平后用后台令牌上传。
   - 本地 `pnpm dev` 启动时自动推一次。
   - 线上写进部署步骤，前台更新后推一次。

   没选“Core 从前台地址拉”，原因是灰度期间线上 Core 的“网站地址”还是旧 Shiro，拉不到。

## 后台

1. **设置 → AI**（`ai-config.tsx`，是手写的表单）：

   - 输入阿拉伯语、希伯来语、波斯语、乌尔都语这类从右往左写的语言时，提示暂不支持。
2. **AI → i18n 子菜单**（新页面，样子照“翻译”页）：

   - 右边是这一组的每一条：中文 | 每种语言的译文，可以直接改。手改过的标“已手改”。

3. **删掉“附加功能 → Yozora 主题”表单**：片段里只剩中文，这个表单最大的用处（三种语言并排填）没有了，日常改片段回到“配置与云函数”。

## 夜航岛播报

现在一共 6 处会播报，按做法分三类：

1. **固定的一句话**：链接已复制、复制失败、评论已发送、悄悄话已发送、登录失败的说明。它们都是界面文字里的条目，界面文字交给 AI 以后，自动跟着当前语言走，不用单独处理。
2. **带文章标题的**：新文章发布、文章修改或删除的通知（`notifications.tsx`），以及“链接已复制”下面那一行标题。
   - 通知是 Core 实时推过来的，里面只有中文标题。外文页面收到后，前台拿文章 id 带 `?lang=` 向 Core 要当前语言的标题：有译文就用译文；刚发布的文章 AI 要过一会儿才翻好，这时就显示中文标题，并标 `lang="zh-CN"`。
   - 代码里现在给标题硬加了中文书名号《》，要挪进界面文字，改成“《{title}》”这样的写法，英文版就能换成引号。
   - “链接已复制”用的是当前页面上显示的标题，外文页面本来就是译文，不用改。
3. **切换语言那一句**：它要用新语言说出来，可这时候页面还是旧语言，只带着旧语言的界面文字。
   - 做法是：页面生成时，给语言菜单附一张小表，每种开着的语言各一句用它自己的语言写好的“已切换到……”，点了哪种就直接从表里取。
   - 每种语言只多一句话，开再多语言也很小。

## 已有的手写译文

`en.ts`、`ja.ts` 里的 382 条英文、日文，以及片段 `i18n` 里的站点文案译文，都用脚本导入成翻译条目，标成“已手改”，AI 就不会重翻，你看到的英文、日文还是现在这样。导入后删掉 `en.ts`、`ja.ts` 和片段里的 `i18n`。删之前备份到 `.local/backups`。线上同样处理，要你同意后再做。

## 限制

- 从右往左写的语言（阿拉伯语、希伯来语等），整页布局要左右翻过来，这次不支持。
- AI 翻的界面文字有时会生硬，可以在“i18n”页逐条改。
- 新加一种语言时，会把几百条界面文字和站点文案翻一遍，Deepseek flash 的费用很低。之后只翻改过的。
- 字体：韩语、法语等用读者电脑自带的字体。首屏的霞鹜文楷只覆盖中日文，其他语言的首屏标题会换成系统字体。
- 碎碎念、思考、一言、评论、友链还是保持中文，这次不动。
- 10-30 定过“翻译只从 Core 来，缺的由 Agent 翻好写进去，不再用 AI 接口补”，这个方案改为由 AI 生成。

## 接口约定（2026-11-05 站长同意全部按推荐做；三边按这里实现，改动先改这里）

### Core 设置（`ai` 配置）

- `enableI18n: boolean`（默认 false）：“启用 AI i18n”。关着时前台只有中文，也不自动生成。
- `i18nLanguages: string[]`（默认 `[]`）：“i18n 语言”，ISO 639-1 代码，用现有的 `normalizeLanguageCode` 归一。读取时去掉 `zh` 和从右往左写的语言（`ar`、`he`、`fa`、`ur`），去重并保持顺序。
- 文章、手记、页面的自动翻译目标语言：开着 `enableI18n` 时取 `translationTargetLanguages ∪ i18nLanguages`；关着时只用 `translationTargetLanguages`。统一用一个小函数算（分类、话题等翻译条目的生成也用它）。

### 翻译条目（`translation_entries`）

新增四种 `keyPath`：

| keyPath | keyType | lookupKey | 原文来源 |
| --- | --- | --- | --- |
| `ui.text` | entity | 界面文字条目名，如 `locale.switched`、`header.presence.label` | 前台上传的原文表 |
| `site.text` | dict | 中文原文的哈希（同心情、天气） | 片段 `theme/yozora` 的 `hero.title`、`hero.description[]` 每一行、`footer.motto`、`copyright`、`techStack.title`、`techStack.description`，以及 SEO 的“网站描述” |
| `project.name` | entity | 作品 id | 作品名 |
| `project.description` | entity | 作品 id | 作品介绍 |

模型新增两个可选字段：`manual?: boolean`（站长手改过或从旧手写译文导入）和 `needsReview?: boolean`（手改过的条目在中文改了之后由 AI 重翻，等站长看一眼）。站长通过接口保存一条译文时 `manual = true`、`needsReview = false`。中文原文变了的条目一律交给 AI 重翻；原来是 `manual` 的，重翻后 `manual = false`、`needsReview = true`。

“翻译词表”页（`GET /ai/translations/entries`）默认不返回这四种。

### 界面文字原文

新集合 `i18n_sources`：`{ key: string（唯一）, text: string, updated: Date }`，存前台最近一次上传的整张原文表。

### 校验（保存前，Core 与前台各做一次）

- 占位符：`{name}` 这种花括号里的英文名字，译文里的集合必须和中文完全一样（不多不少）。
- 强调标记：`**` 出现的次数必须和中文一样。
- 译文去掉首尾空白后不能是空的。

对不上的不存（不写库），这一条就算“缺译文”，前台显示中文。

### AI 提示词

新增一份 `uiTranslation(targetLang, fields)`（同 `fieldTranslation` 的结构化输出格式）：网站界面文字和站点文案，简洁自然；`{占位符}` 原样保留、不翻译不改名；`**…**` 包住的强调词，译文里把 `**` 放到对应的词上；Yozora、GitHub、RSS、LeetCode 这类品牌和技术名词不翻；不加解释。每批最多 60 条，按条目名排序后分批。

### 接口（前缀 `/ai/i18n`）

公开（不要登录，走 Core 的接口缓存，`I18N_UPDATE` 时清缓存）：

- `GET /ai/i18n` → `{ enabled: boolean, languages: string[] }`。关着时 `languages` 是 `[]`。
- `GET /ai/i18n/:lang` → `{ lang, messages: { [界面文字条目名]: 译文 }, site: { [中文原文]: 译文 }, projects: { [作品 id]: { name?: string, description?: string } } }`。只含已经翻好、通过校验的。`lang` 不在开着的语言里返回 404。

要登录（给后台和本机脚本，后台令牌 `x-api-key` 也行）：

- `PUT /ai/i18n/source`，body `{ messages: { [条目名]: 中文 } }`：整张替换原文表。返回 `{ added, changed, removed }`（条目名列表）。删掉的条目连同它的 `ui.text` 译文一起删。开着 `enableI18n` 时，在后台异步翻新增的和改过的（不等它翻完就返回）。
- `GET /ai/i18n/status` → `{ running: boolean, lastRun?: { at, created, failed, skipped } , languages: string[], enabled: boolean }`。
- `POST /ai/i18n/generate`，body `{ langs?: string[], group?: string, onlyMissing?: boolean }`：异步开始一次生成（已经在跑就返回 409），立刻返回 `{ started: true }`。不传 `onlyMissing` 时，缺的和中文改过的都翻。
- `GET /ai/i18n/groups` → `[{ group, total, languages: { [lang]: { done, missing, review } } }]`。`group` 规则：`ui.text` 取条目名第一段（`header`、`home`……），`site.text` 是 `site`，`project.*` 是 `projects`。
- `GET /ai/i18n/entries?group=xxx` → `[{ keyPath, lookupKey, key, source, translations: { [lang]: { text, manual, needsReview } | null } }]`。`key` 对 `ui.text` 是条目名，对 `site.text` 是中文原文本身，对 `project.*` 是“作品名 / 介绍”加作品 id。
- `PUT /ai/i18n/entries`，body `{ keyPath, lookupKey, lang, text }`：手改（不存在就新建），先过校验（不通过返回 422 和原因），保存后 `manual = true`、`needsReview = false`，发 `I18N_UPDATE`。
- `DELETE /ai/i18n/entries`，body `{ keyPath, lookupKey, lang }`：删掉一条译文（回到缺译文）。

### 自动生成的时机（都要求 `enableI18n` 开着且配了 AI 服务商）

- 上传原文后：翻新增和改过的界面文字。
- 片段 `theme/yozora` 新建或保存、SEO 设置保存、作品新建或修改：重新收集站点文案和作品，翻新的和改过的，删掉用不到的旧 `site.text` 条目；作品删除时删它的两条。
- `i18nLanguages` 新加了语言：把这种语言的界面文字、站点文案、作品全部翻一遍。

### 事件

- 新增 `I18N_UPDATE`（登记进 `BusinessEvents` 和 Webhook 可选事件），载荷 `{ langs: string[] }`（不含文字内容）。生成写入了条目、手改、删除、上传原文删掉条目时发。
- `i18nLanguages`、`enableI18n` 变化走已有的 `OPTION_UPDATE`。

### 前台

- 词典：`zh.ts` 是中文原文；带参数的条目写成 `msg("已切换到{name}")`（返回函数，组件调用不变），带判断的拆成几条。条目名 = 对象路径用点连起来（`locale.switched`）。
- 推送：`scripts/push-i18n-source.mjs [--prod]` 用 `.local/publish.json` 的令牌 `PUT /ai/i18n/source`；`pnpm dev` 启动时自动推一次本地。
- 取译文：`getT()` 读 `GET /ai/i18n/:lang`（`"use cache"`，标签 `i18n`），逐条过同样的校验，缺的和不合格的用中文；语言列表读 `GET /ai/i18n`（标签 `i18n`）。Webhook 收到 `I18N_UPDATE`、`OPTION_UPDATE` 时让 `i18n` 失效。
