# 站点文案只写中文、AI 补译、按勾选的语言显示（方案，待站长确认）

2026-11-05 站长的想法：配置片段 `theme/yozora` 里只写中文；英文、日文由后台的 AI 自己翻出来，不用手写；有一个地方勾选要哪些语言，前台就只出现这些语言；没有译文的地方由 AI 补上。

本文只是方案，还没有改任何代码。

## 现在是怎么做的

- 首屏标题和说明、页脚那句话、版权说明、技术栈的标题和说明，中文写在片段里，英文、日文手写在同一个片段的 `i18n.en`、`i18n.ja` 下面。站点描述的译文、作品名和介绍的译文也手写在那里。前台按语言挑出来显示（`apps/web/lib/theme-config.ts`）。
- 之所以手写，是因为 Core 的 AI 翻译只管两类：
  - 文章、手记、页面的正文。
  - “翻译条目”里固定的五种短文字：分类名、话题名、话题简介、心情、天气。
  
  配置片段、站点描述、作品都不在 Core 的翻译范围里。
- Core 的“翻译条目”机制已经很完整：
  - AI 设置里有“开启 AI 翻译”“AI 翻译自动生成”和“AI 翻译目标语言”。本地库这三项分别是开、开、`["zh","en","ja"]`，配了 1 个 AI 服务商。
  - 分类、话题这些一保存就自动生成译文；中文没变就不重翻，中文改了才重翻。
  - 后台“AI → 翻译条目”页可以手动“生成翻译”，也可以逐条改 AI 的译文。
  - 前台请求时带上 `?lang=en`，Core 自动把返回内容里的这些字段换成译文。
- 前台支持哪些语言写死在 `apps/web/lib/i18n/config.ts`：中、英、日。按钮、菜单这些界面文字（几百条）是代码里的三份词典。

## 方案：把站点文案接进 Core 的“翻译条目”

整体流程如下：

1. 站长在片段里只写中文。
2. Core 把这些文字收进翻译条目，由 AI 生成译文。站长也可以在“翻译条目”页手改。
3. 前台带 `?lang=` 读片段，Core 把中文换成译文后返回。
4. “AI 翻译目标语言”同时就是前台的语言开关。

下面分 Core、前台、后台三块说。

### Core

1. **新增三类翻译条目。**
   - “站点文案” `site.text`：和心情、天气一样，按中文原文查。范围是片段里的 `hero.title`、`hero.description` 的每一行、`footer.motto`、`copyright`、`techStack.title`、`techStack.description`，加上 SEO 的“网站描述”。
   - “作品名” `project.name`、“作品介绍” `project.description`：和分类名一样，按作品 id 查。
2. **收集和自动生成。**
   - `collectSourceValues` 增加这些来源，后台“生成翻译”按钮会一并处理。
   - 保存片段 `theme/yozora`、保存 SEO 设置、增删改作品时，按“AI 翻译自动生成”开关自动生成。只翻新增的和中文改过的。
3. **AI 提示词。** 现有的短字段提示词是为一到五个词的分类名写的。站点文案是整句，需要单独一条规则：
   - 保持语气。
   - 中文里 `**…**` 包住的强调词，译文里要把 `**` 放到对应的词上。比如“一个在深夜写代码的**大三学生**”应该翻成“Coding by night, a **third-year student**”。
4. **把译文交给前台。**
   - 公开的 `GET /snippets/theme/yozora?lang=en` 把上面那几个字段换成译文。只处理这一条片段，别的片段原样返回。
   - `GET /projects?lang=en` 换作品名和介绍。
   - 公开的聚合接口带上站点描述的译文，以及“AI 翻译目标语言”这份列表。列表不含密钥，可以公开。
5. **清理旧条目。** 中文改了以后，旧中文对应的条目没用了。生成时顺手删掉片段里已经不存在的 `site.text` 条目，免得在“翻译条目”页里越积越多。

### 前台

1. **改为读 Core 换好的内容。** `theme-config.ts` 不再读片段里的 `i18n`：
   - 外文页面带 `?lang=` 读片段和作品。
   - 和中文版逐项比较，没翻出来的项照旧显示中文，并标 `lang="zh-CN"`（文章列表现在就是这么做的）。
   - 片段读不到时的占位文案保留现在这三份。
2. **语言开关。**
   - 前台真正开放的语言 =“AI 翻译目标语言” ∩ 前台有界面词典的语言（目前是英、日）。中文一直开着。
   - 没开的语言：语言菜单、手机菜单、文章页的语言分段、sitemap 都不出现；`/ja/...` 这类旧链接跳回同一页的中文。
   - `proxy.ts` 按浏览器语言自动跳转时，也只在开放的语言里挑。
3. **刷新。** 改了翻译条目（Core 发 `TRANSLATION_*` 事件）或改了 AI 设置（`OPTION_UPDATE`）后，片段、作品、语言列表的缓存要跟着失效。这两个事件 Webhook 现在都已经在听，只需要把缓存标签对上。

### 后台

1. “翻译条目”页给新的三类加上名称：站点文案、作品名、作品介绍。
2. “AI 翻译目标语言”还是现在的列表输入框。在说明里写明前台目前只支持 `en`、`ja`，填了别的语言，文章会被翻译，但前台不显示。
3. **删掉“附加功能 → Yozora 主题”表单。** 片段只剩中文以后，它最大的用处（三种语言并排填）就没了，日常改片段回到“配置与云函数”。

## 已有的手写译文怎么办

片段里现在有一批手写的英文、日文：首屏、页脚、版权说明、技术栈、站点描述、作品。迁移时用脚本把它们导入成翻译条目，原文是中文，译文是现有的手写版本，AI 就不会重翻，你也不会突然看到不一样的英文。导入完再从片段里删掉 `i18n`。删之前把原片段备份到 `.local/backups`。线上同样处理，需要你同意。

## 做不到或者要另外做的

- **只能选中、英、日。** 加韩语这样的新语言，要先补一份界面词典（几百条按钮、菜单文字），那是另一件事。
- **AI 会产生调用费用。** 站点文案只有十几条，改一次几乎可以忽略。线上的 AI 设置有没有配好、目标语言填了什么，部署前要先确认。
- **10-30 定过“翻译只从 Core 来，缺的由 Agent 翻好写进去，不再用 AI 接口补”。** 这个方案改为由 AI 生成，Agent 不再手写。分类名、话题这些本来就是 Core 的 AI 在翻，不受影响。
- 碎碎念、思考、一言、评论、友链还是保持中文，这次不动。

## 分步做，每步单独提交

1. Core：新增三类条目、收集、自动生成、提示词、片段和作品接口按 `?lang=` 换译文、清理旧条目、聚合接口带语言列表。用 Core 自己的测试验证：改中文后自动生成、`?lang=en` 返回译文、强调词的 `**` 还在、别的片段不被改。
2. 前台：改为读 Core 换好的内容，删掉读 `i18n` 的代码。现有的 `i18n-content.mjs` 等测试要继续通过。
3. 前台：语言开关（菜单、跳转、sitemap、旧链接）。新加一个 e2e：把目标语言改成只有英文时，日文从菜单里消失，`/ja/posts` 跳回 `/posts`。
4. 后台：翻译条目页的名称；删掉 Yozora 主题表单和它的测试。
5. 本地数据迁移：导入现有译文、删掉片段里的 `i18n`。
6. 线上：重建 Core、前台、后台，迁移线上数据。需要你同意后再做。
